# 공용 풀 운영 안내

작성 2026-08-10. 대상: 사장님(운영 판단) + 이후 작업자(연결 절차).

---

## 1. 한 줄 요약

**수집을 사람마다 하던 걸 그만두고, 우리가 한 번 모아서 전원이 검색한다.**

바뀐 것은 단 하나, "누가 데이터를 사느냐"다.

| | 이전 | 지금 |
|---|---|---|
| 누가 수집하나 | 사용자마다 각자 | 우리가 중앙에서 한 번 |
| 100명이 "다이어트"를 찾으면 | 100번 산다 | 1번 산다 |
| 사용자가 1만 명이 되면 | 원가도 100배 | **원가 그대로** |
| 검색할 때 | 돈이 나간다 | 돈이 안 나간다 (DB 조회) |

## 2. 하루에 얼마가 나가나

공급사 단가는 1회 요청 **2.59원**(Freelance $47 / 25,000크레딧 기준, `COST_STRUCTURE.md` 4-3).

| 항목 | 수치 | 환산 |
|---|---|---|
| 실행 크론 일정 | 하루 8회 (3시간 간격) | |
| 회차당 처리 | 최대 8건 × 요청 2회 = 16회 | |
| **하루 실제 최대** | **128회** | **332원 / 월 약 9,900원** |
| 브랜드 시드 한 바퀴 | 107개 × 2 = 214회 | 554원 (첫날·이튿날에 대부분 소화된다) |
| DB 하드캡 (`crawl_budget.calls_limit`) | 420회 | 1,088원 / 월 32,600원 |

하루 8회인 이유는 Vercel Hobby 가 **크론 하나당 하루 1회**만 허용하기 때문이다
(자세한 건 `vercel.json` 참고 — 같은 경로를 시각만 달리해 8개로 쪼갰다).
Pro 로 올리면 한 줄로 합치고 회차·처리량을 함께 키우면 된다.

**이 금액은 가입자 수와 무관하다.** 1명이든 1만 명이든 같다.
늘리고 싶으면 `crawl_budget.calls_limit` 한 숫자만 올리면 되고, 그게 상한의 전부다.

검색어 361개(일반 254 + 브랜드 107)를 한 바퀴 도는 데 722회(1,870원)가 든다
→ 현재 속도로 **약 5.6일에 전 업종이 한 번 갱신**된다.
브랜드가 우선순위 20이라 **첫 이틀 안에 아는 이름부터 깔린다.**

### 상한이 진짜로 지켜지는 이유

공급사를 호출하기 **전에** DB 함수 `claim_crawl_budget()`이 잔량을 원자적으로 깎는다.
0이 나오면 그 자리에서 멈춘다. 크론이 두 번 뜨든, 서버가 여러 대로 뜨든,
누가 크론 URL을 손으로 여러 번 치든 하루 지출은 이 숫자를 넘을 수 없다.

## 3. 켜는 순서

### (1) 마이그레이션 적용 — Supabase SQL 편집기에서 순서대로

```
0027_shared_pool.sql        공용 풀 표 + 불변식 트리거
0028_pool_ops.sql           예산 하드캡 + 작업 큐
0029_personal_saves.sql     저장·보드·검색 이력
0030_industry_seed.sql      업종 22개 + 시드 검색어 253개
0031_migrate_keywords.sql   기존 사용자 등록 검색어를 크롤 목록으로 승격
0032_lock_pool_functions.sql 운영 함수 실행 권한 회수 ← 반드시 같이 적용
0033_brand_seed.sql         유명 브랜드 107개 (최우선 수집)
0034_heat_base.sql          저장수 부스트 원본 보관 (없어도 크론은 안 죽는다)
```

0031은 기존 사용자가 있을 때만 의미가 있다. 없어도 실행에는 문제 없다.

**0032는 건너뛰면 안 된다.** Postgres가 새 함수의 실행 권한을 기본으로 전체 공개로
주기 때문에, 0032 전에는 공개 anon 키만으로 `claim_crawl_budget`을 직접 부를 수 있다.
음수를 넣으면 사용량 카운터가 0으로 돌아가므로 **하루 지출 상한이 무력화된다.**
0032가 그 권한을 회수하고 service_role(크론)에만 다시 준다.
0032 끝에 붙은 SELECT가 0027~0031 적용 결과를 표로 보여준다.

### (2) Storage 버킷 확인

`reference-thumbs` 버킷이 이미 있으면 그대로 쓴다(경로만 `pool/` 아래로 분리된다).

### (3) 첫 수집 — 여기서 처음 돈이 나간다

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://finch.ai.kr/api/cron/pool-plan
```

계획만 세운다. **돈이 나가지 않는다.** 응답의 `queued` 숫자로 큐가 몇 개 잡혔는지 확인한다.

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://finch.ai.kr/api/cron/pool-work
```

여기서 실제로 호출한다. 1회 실행 = 최대 16요청 = 약 41원(MAX_JOBS_PER_RUN 8 × CURSOR_PAGES 2, 30행 표와 같은 값). 응답의 `callsUsed`·`newCreatives`를 본다.

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://finch.ai.kr/api/cron/pool-finalize
```

썸네일을 채우고 업종 노출 자격을 계산한다. **공급사 크레딧 0.**

이후로는 `vercel.json`의 크론이 알아서 돈다(KST 기준):

| 크론 | 시각 |
|---|---|
| 계획 `pool-plan` | 05:00 |
| 실행 `pool-work` | 05:30 · 08:30 · 11:30 · 14:30 · 17:30 · 20:30 · 23:30 · 02:30 |
| 마감 `pool-finalize` | 03:30 |

계획이 큐를 채운 뒤 30분 만에 첫 수집이 돈다. 큐가 비어 있는 회차는 그냥 넘어간다(돈 안 나감).

### (4) 화면 전환은 자동

풀에 내용이 생기는 순간 레퍼런스 화면이 풀을 보여준다. 켜야 할 스위치가 없다.
비어 있는 동안에는 기존 개인 수집분이 그대로 보이므로 중간에 빈 화면이 뜨는 구간이 없다.

---

## 4. 업종이 화면에 뜨는 조건

업종 22개를 만들었지만 처음부터 다 보이지는 **않는다**.

> 브랜드 4곳 이상 **그리고** 소재 40건 이상

두 조건을 동시에 넘긴 업종만 `pool-finalize`가 자동으로 켠다(`is_visible`).
사람이 손으로 켜는 스위치를 두지 않았다. 손으로 켜면 반드시 빈 업종이 화면에 뜨고,
빈 칸 하나가 "데이터 없는 서비스"라는 인상을 만든다.

한쪽 조건만 보지 않는 이유: 소재 200건이 전부 한 브랜드에서 나온 업종이 통과하면
그 업종 화면이 같은 광고주로 도배된다.

## 5. 스스로 자라는 구조

사용자가 검색했는데 결과가 0건이면 그 검색어가 `search_history`에 남는다.
플래너가 다음 회차에 **그 검색어를 최우선으로** 수집한다.

우선순위는 이 순서다. 이게 곧 서비스 성격이다.

| 순위 | 대상 | 이유 |
|---|---|---|
| 1 | 팔로우된 브랜드 | 돈 낸 사람이 지켜보는 대상. 제일 먼저 신선해야 한다 |
| 2 | 결과 0건이었던 사용자 검색어 | 실제 수요인데 풀에 구멍이 난 자리 |
| 3 | 자격 미달 업종의 시드어 | 빈 업종을 채우는 게 전체 품질을 가장 크게 올린다 |
| 4 | 나머지 순환 | 오래된 것부터 |

반대로 전 업종을 균등 순환시키면 아무도 안 찾는 업종에 예산을 흘리면서
정작 유료 사용자가 보는 화면은 안 바뀐다.

세 바퀴를 돌았는데 계속 빈손인 검색어는 자동으로 비활성화된다.

## 6. 폐기한 것

`/api/cron/collect-references` — 사용자별 자동수집. 라우트는 남겼지만 꺼짐을 반환한다.

두 가지가 깨져 있었다.

1. **원가가 사용자 수에 비례했다.** 겹치는 키워드에서 절감이 0이었다.
2. **회차 상한이 가입 순 50명 고정이고 순환이 없었다.** 51번째부터는 영원히 차례가
   오지 않는다. 늦게 가입한 유료 사용자가 기능을 못 받는 상태였다 — 비용 문제가 아니라
   환불 사유다.

사용자가 직접 누르는 "지금 수집"은 그대로 살아 있다.

| 항목 | 왜 안 했나 |

| 소재 상세 모달 확대 전환 | 카드 밀도·그리드 개편을 먼저 확정했다 |

## 8. 크레딧이 떨어지면

`OWNER_EMAIL` 을 Vercel 환경변수에 넣어 두면, 수집이 멈추는 순간 그 주소로 메일이 간다.

| 경보 | 언제 | 뜻 |
|---|---|---|
| 공급사 크레딧 소진 | 공급사가 402 를 돌려줄 때 | 크레딧을 채워야 재개된다 |
| 오늘 예산 소진 | `calls_limit` 도달 | 내일 자동 재개. 급하면 상한을 올린다 |

같은 경보는 20시간에 한 번만 보낸다 — 3시간마다(하루 8회) 도는 크론이 매번 보내면
그 순간부터 아무도 안 읽는다.

크레딧을 채우면 **따로 켤 것이 없다.** 대기 중이던 작업이 그대로 남아 있어
다음 회차부터 이어서 돈다.

> 무료 계정을 새로 만들어 돌리는 방식은 한 가지 위험이 있다. 공급사가 이를 감지하면
> 계정을 막을 수 있고, 그러면 풀 전체가 멈춘다. 이 서비스의 가장 큰 위험은 소송이
> 아니라 **공급 중단**이라고 이미 정리해 뒀다(`docs/COST_STRUCTURE.md`).
> 실제로 쓸 만하다는 게 확인되면 $47 유료 전환이 안전한 선택이다.
