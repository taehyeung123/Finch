# 리틀리(litt.ly) 프로필링크 에디터 해부 — 핀치 흡수 계획 (2026-08-22)

실측 방법: 사장님 계정으로 `app.litt.ly`의 페이지·디자인·분석·관리·마케팅 탭과 페이지 설정 모달을 전부 열어 캡처,
Redux 스토어에서 **페이지 데이터 모델**을 읽고, 메인 번들(`main.*.js`, 11MB)에서 **한국어 UI 문자열 1,618개**와
열거값(레이아웃·버튼 효과·판매 타입 등)을 추출해 편집 옵션을 화면에 뜨지 않는 것(유료 잠금)까지 확인했다.
코드 복제는 하지 않는다 — 기능·데이터 모델만 참고해 우리 구조로 재구현한다.

## 1. 리틀리 에디터 구조 (실측)

- **배치**: 좌측 고정 폰 미리보기(전체 높이, 하단 `URL litt.ly/xxx` + 수정·복사·공유), 그 왼쪽에 ⚙ 페이지 설정·＋ 페이지 추가.
  우측 카드에 탭 5개 `페이지 · 디자인 · 분석 · 관리 · 마케팅`.
- **페이지 탭 = 블록 아코디언 목록** (캔버스 직접 편집 없음). 블록 카드 헤더: 드래그 핸들 · ON/OFF 스위치 · 타입 아이콘+이름 ·
  `강조★` · `예약🕐` · `⋯`(블럭 복사 / 블럭 삭제 / 페이지 이동 / 홍보) · 접기 화살표. 펼치면 그 자리에서 인라인 편집.
  하단 `+블럭 추가` → 카탈로그 모달(4 카테고리 24종). 수정은 즉시 자동 저장(debounce), 미리보기 즉시 반영.
- **블록 공통 모델**: `key, type, use(on/off), folded, emphasized(하단 고정 CTA 1개), reservation{openAt, closeAt}(예약 공개/숨김),
  tags, searchable, bypassQuery, price/originalPrice, peerLink`.
- **페이지 모델**: `alias, meta{title,description,robots}, og{image,title}, favicon{text,image}, secret{enabled,body,image}(비밀번호 페이지),
  locale{ko,en,ja}, subpages[], marketing{pixelId,gaMeasurementId,gaTrackingID,utmSource,utmMedium}, linkOpenInNewTab,
  externalBrowserPopup{tiktok}, certificated`.
- **프로필 모델**: `use, layout(portrait…), font.size(normal/medium/large), image, backgroundImage, title, subtitle, folded,
  subscriptionFields{email,phone}`.
- **테마 모델**: `backgroundColor | backgroundImage + backgroundImageFilter(none/light/dark/blur/darkBlur)`,
  `buttonColor + savedButtonColors(배경별 기억) + customButtonColor`, `buttonColorLayout(default=부분 적용 / inverted=전체 적용)`,
  `buttonShape(rounded / fullyRounded / sharp)`, `buttonEffect(none / circleFill / wave / flip / swipe)`, `font.family`,
  `logo{type default/image/hidden, position top/bottom}`, `topbar{type}`, `showingShareButton, showingSubscriptionButton`,
  `desktopViewLayout(phone / profileAndPhone)`.

## 5. 결론 — 흡수 가능한가

**가능하다.** A단계 전부가 외부 결제·정산 없이 우리 구조(블록 jsonb + 테마 jsonb + 스냅샷 발행)에 그대로 얹힌다.
필요한 DB 변경은 블록 `type` check 확장 + `link_pages` 에 `settings jsonb`(비밀번호·새창·언어·로고·상단메뉴) 1개, 방명록 테이블 1개, 분석에 device/referrer/dwell 컬럼.
B단계(판매·예약·멤버십·광고·스토어 동기화)는 PG·정산·세금 인프라가 본체라 CLAUDE.md 원칙대로 맨 마지막에 인터페이스만 두고 목 처리한다.

**UI 방향 제안**: 캔버스 직접 편집(우리 우위)은 유지하고, 가운데 패널에 리틀리식 **블록 아코디언 목록**을 기본 화면으로 둔다
(카드 헤더: 핸들·ON/OFF·아이콘·이름·강조★·예약🕐·⋯·접기, 펼치면 인라인 편집). 캔버스 클릭 = 그 카드가 펼쳐지며 스크롤.
즉 "목록에서 관리, 캔버스에서 확인·미세 편집" 두 길을 모두 연다.
