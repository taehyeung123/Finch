### 스레드 (`lib/meta/threads-oauth.ts` 가 3개를 요청 — 답글 2개는 2026-09-11 뺐다)

| 핀치 기능(화면) | 권한 | 비고 |
|---|---|---|
| 연동, 홈 프로필·최근 글 | `threads_basic` | |

**스레드에는 자동 DM 을 만들 수 없다**(2026-09-11 메타 문서 확인). 스레드 API 에는 메시지 엔드포인트·권한·웹훅이 하나도 없다 —
권한 목록 12개(`threads_*`)·API 레퍼런스 9개 묶음·웹훅 4종(replies·mentions·delete·publish)·변경 기록(2024-04~2026-08) 어디에도 없다.
스레드 앱 안의 DM 은 2025-07 에 생겼지만 외부 앱에 열리지 않았다(인스타 메시징 API 로도 닿지 않는다).
답글 권한 2개로 되는 것은 **공개 답글**뿐이다 — 내 글에 달린 답글 읽기(`/{media}/replies`·`/conversation`), 답글 달기(`reply_to_id`),
숨기기/보이기(`/manage_reply`), 답글 허용 범위, 답글 승인. `replies` 웹훅도 있다(승인·고급 액세스 뒤). 하루 답글 한도 1,000개.
그래서 스레드판 자동화는 «댓글 → 자동 **공개** 답글»이다 — 모두에게 보이고 버튼이 없어 인스타의 «댓글 달면 DM 으로 링크» 흐름은 옮겨지지 않는다.
고객 화면 `app/(finch)/(marketing)/instagram/auto-dm/page.tsx` 의 스레드 설명이 없는 기능(«댓글 공개 답글 자동화는 가능»)을 약속하고
«스레드 앱에 독립된 메시지함이 없다»는 옛 사실을 적고 있었다 — 2026-09-11 에 고쳤다(같은 파일의 «페이스북 페이지 필요»도 인스타 로그인 방식엔 틀려서 함께 고쳤다).

### 심사가 필요 없는 것

레퍼런스 › 탐색(콘텐츠·메타광고·틱톡·스레드), 스크랩, 경쟁사 화면은 **플랫폼 API 를 안 쓴다** —

심사 대상은 아니지만, 공식 문서가 «웹 화면 긁기는 약관 위반»이라고 적은 정책 위험은 남는다(`docs/REAL_API_SPEC.md`).

## 4. 제출 전에 남은 일

### 4-1. Claude(코드)

1. **자동 DM «지금 확인» 버튼** — 게시물 댓글을 직접 읽어 규칙대로 DM 을 보낸다. 심사 전 시험과 **심사 녹화**에 쓴다.
   댓글 알림(웹훅)은 앱이 Live 가 되고 승인이 난 뒤에야 오기 때문에, 이것 없이는 심사자가 자동 DM 을 재현할 방법이 없다.
   (2026-09-11 제안, 사장님 「만들어」 대기)
2. ✅ **스레드 답글 권한 2개 정리 — 2026-09-11 (a)로 결정·반영**(스코프 3개, 소개 페이지 문구 수정). 결정 전 비교는 아래에 남긴다:
   (a) 요청 목록에서 뺀다 — 녹화 2편이 줄고 9/18 제출에 영향이 없다. 나중에 스레드 자동 답글을 만들면 그때 다시 심사받고, 이미 연결한 사람은 다시 연결해야 한다.
   (b) 스레드 자동 **공개** 답글을 지금 만든다 — 녹화 15편. 최소판(게시물 고르기 → 댓글 가져오기 → 공개 답글, «지금 확인» 방식)이 파일 5~6개,
       정식판(웹훅·크론·요금·약관 문구까지) 3~5일 추정. 자동 DM 표에 채널 칸이 없어 마이그레이션이 필요하고,
       `flush-dms` 크론이 스레드 줄을 인스타 비공개 답장으로 보내지 않게 채널로 걸러야 한다.
3. **광고 권한 보강** — 스코프는 **동의 시점에 굳으므로** 녹화 전에 끝내야 한다(바꾸면 다시 연동하고 다시 호출해야 한다).
   - `business_management` 를 요청 목록에 넣고, 그걸 실제로 쓰는 곳을 만든다(예: 비즈니스 포트폴리오별 광고 계정 목록).
   - `pages_read_engagement` 녹화용으로 **페이지 최근 게시물 보기**를 만든다(예: 광고 게시 페이지를 고를 때 그 페이지의 최근 게시물을 보여 준다).
   - `instagram_basic` 은 넣지 않는다(위 표).
4. **권한 확인 가드** — 자동 DM·웹훅·스튜디오 예약은 필요한 권한이 있는지 안 본다(발행만 본다). 권한 없이 연동한 계정이
   조용히 실패하지 않게 막는다.
5. **영어 제출 문구** — 권한마다 따로(복붙 금지), Platform Settings 단계별 지침, 녹화 대본. 초안 0be686e5 는 한국어이고
   스레드 답글·예약 발행 기준이며 광고가 4개 권한뿐이라(`business_management` 없음) 고쳐 써야 한다.
6. **심사자 계정에서 운영자 전용 안내 숨기기** — `OWNER_EMAIL` 에 넣으면 설정 › SNS 계정 연결 위에 «고객에게는 아직 닫혀 있다» 안내와
   연동 실패 원문이 보인다(`settings/channels/page.tsx`). 심사자에게 «미완성»으로 읽힐 수 있어 첫 번째 주소(사장님)에게만 보이게 한다.
7. **페이앱 연동** — 계약 후 키를 받아야 끝낼 수 있다. 토스 배관은 교체 대상이다(`docs/API_ROADMAP.md` 결제 절은 아직 토스 기준).

### 4-2. 사장님

1. **심사용 구글 계정** 만들기 → Vercel `OWNER_EMAIL=본계정,심사용계정` (본계정이 첫 번째) → 재배포 →
   그 계정으로 핀치 로그인해 온보딩·약관 동의까지 통과. ⚠️ 새 구글 계정은 해외 로그인에 본인확인을 걸 수 있다 — 여기가 가장 큰 위험.
2. **심사자가 연결해 볼 인스타 계정** — 개발 모드에선 테스터 계정만 연결된다. 테스트용 `sding.kr` 의 로그인 정보를 제출서 «자격 증명» 칸에 넣는다
   (해외 로그인 확인이 걸리지 않게 미리 정리). 스레드도 같은 계정이 테스터인지 확인. **자동 DM 시연용 댓글은 다른 계정이 달아 둔다** — 연결된 계정 자신의 댓글은 코드가 무시한다.
3. **스레드**: 권한 2개(`threads_content_publish`·`threads_manage_insights`) 「앱 검수에 추가」 — 답글 2개는 **누르지 않는다** →
   §4-1-2 가 배포된 뒤 핀치에서 스레드 **다시 연결** → 홈 한 번 보기(insights) → 스레드 「지금 발행」 1건.
4. **광고**: §4-1-3 이 배포되면 핀치에서 Meta 광고 **다시 연결**(새 권한 허용) → 계정 및 설정 › SNS 계정 연결 › «광고 게시 페이지» 줄의
   「페이지 선택」을 한 번 열기 → `pages_*`·`business_management` 호출이 찍힌다.
   그리고 **광고 화면을 매일 써서 호출을 쌓는다** — 호출 등급(Full)은 15일 동안 성공 500회가 있어야 신청된다(지금 41회).
5. **녹화** — 권한당 한 편, 재사용 금지. 로그아웃 상태에서 시작, 소리 없음, 영어 캡션, 1080p·너비 1440px 이하.
   편수는 스레드 답글을 빼면 **13편**(인스타 5 · 스레드 3 · 광고 5).
   메시지 권한 영상에는 **앱이 보낸 DM 이 인스타 받은편지함에 보이는 장면**과 **명령어(cURL) 발송 장면**이 들어간다(대시보드의 API 도우미 사용 가능 — 메타 권한 문서).
6. **앱 기본 설정** — 아이콘 1024×1024, 개인정보처리방침 `finch.ai.kr/privacy`, 카테고리, 연락 이메일 support@finch.ai.kr.
   데이터 삭제·연동 해제 콜백 주소(인스타·스레드·광고 각 2개, 코드는 `app/api/auth/*/deauthorize`·`data-deletion`)가 등록돼 있는지도 본다 — 대시보드 확인 필요.
7. **제출** — 앱은 **개발 모드(게시되지 않음) 그대로**. 제출 화면에서 `business_management`·`public_profile` «액세스 늘리기»가 들어갔는지 본다.
8. **페이앱 판매자 가입·서류 제출** — 메타와 무관하게 지금 바로 할 수 있다. 페이앱 안내(2026-09-11 확인,
   payapp.kr 가이드): 가입은 무료이고 **연동 개발은 바로 시작할 수 있다**. 결제는 서류 전에도 받을 수 있지만 **첫 정산은 계약 뒤**다.
   법인 서류는 인감 날인 계약서 2부 · 법인인감증명서 · 사업자등록증 사본 · 법인 통장 사본, **심사 약 2영업일**.
   함께 물어볼 것: ① SaaS 구독+크레딧 판매가 «유의 업종»인지(수수료가 달라진다) ② **정기결제를 따로 승인받아야 하는지**(사이트에 없다)
   ③ 연동 키(userid·linkkey·linkval) 발급.

## 5. 떨어지는 이유

- **심사자가 못 들어오면 제출 전체가 거부된다** — 권한 하나가 아니라 통째로. 핀치는 구글·카카오 로그인뿐이라 심사용 구글 계정이 유일한 문이다.
- **가짜 페이스북 계정** 정보를 내면 전체 거부 — 만들지 말 것.
- **안 쓰는 권한 요청** — 스레드 답글 2개가 그랬다(2026-09-11 뺐다). 권한을 새로 넣을 땐 쓰는 화면부터 만든다.
- **심사자가 기능을 재현 못 함** — 가장 흔한 사유. 자동 DM 이 여기 걸린다(§4-1-1).
- **한 영상에 권한 여러 개 / 설명 복붙** — 그 권한 반려.
- **광고 소재 만들기는 개발 모드에서 막힐 수 있다**(오류 1885183 추정) — 광고 녹화는 켜기·끄기로 보여 준다.
- **호출이 30일을 넘기면** 다시 채워야 한다 — 제출이 늦어지면 날짜를 다시 본다.
- **승인 전에 Live 로 돌리면 승인 안 된 권한은 테스터도 못 쓴다**(메타 제출 안내) — 녹화·시험이 전부 막힌다. 제출도 개발 모드로 한다.
- **미완성으로 보이는 화면 / «나중에 쓸» 권한** — 반려 사유로 명시돼 있다.
- **광고는 심사자가 페이스북 계정으로 들어와야 한다** — 개발 모드에서 심사자에게 역할 제한이 풀리는지 명문 규정을 못 찾았다(확인 필요).
  가짜 페이스북 계정·사장님 개인 계정 비밀번호는 줄 수 없다 — 녹화와 단계별 안내를 특히 꼼꼼히.

## 8. 승인 뒤 순서 — 틀리면 고객이 벽에 부딪힌다

1. 앱 Live 전환(메타). 승인 없이 Live 만으로는 부족하고, Live 없이 승인만으로도 부족하다.
2. 사장님 계정으로 실연동 한 번 더.
3. **마지막에** `CHANNELS_OPEN` 에 승인된 채널만 추가하고 재배포.
4. 틱톡은 포털 상태가 Live 가 되면 같은 방법으로 `tiktok` 추가. **포털의 Recall 은 제출 취소 버튼 — 누르지 말 것.**
5. 메타 승인 뒤에는 **해마다 «데이터 사용 점검»**(Data Use Checkup)을 해야 권한이 유지된다(메타 접근 수준 문서).
