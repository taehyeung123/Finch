## 초안을 쓴 뒤 코드로 해결한 것 (2026-09-11)

초안 본문에는 아래 항목이 «할 일»로 남아 있을 수 있다 — **이미 반영됐다.**

- **«지금은 임시오픈 기간입니다» 안내** — 심사용 계정(`OWNER_EMAIL` 두 번째 이후 주소)에는 아예 뜨지 않는다(`app/(finch)/(app)/layout.tsx`).
  그리고 모든 사용자에게, 인가 화면에서 돌아온 방문(`?connect=`·`?linked=`)에는 뜨지 않는다 — 결과 모달(z-50)을 덮던 버그(`components/layout/opening-notice.tsx`).
  → 녹화·심사자 안내에서 «오늘 하루 종일 보지 않기»를 누르라는 단계는 **빼도 된다.**
- **광고 표 «도달» 칸** — `ads_read` 녹화 요건(노출·집행액·클릭·**도달**)에 맞춰 캠페인 표에 추가했다(`ads/_components/live-campaign-table.tsx`).

## 발행 작성기 개편 반영 (2026-09-12, `3366fe1`·`40355b5`)

초안은 옛 작성기(사진만·합계 3MB·base64 전송) 기준이었다. 새 작성기(사진·영상 섞기·브라우저 직접 업로드·«처리 중»·«게시물 보기»)에 맞춰
INSTAGRAM §3·THREADS §2·SHARED 안내문(3·5·6절)과 라벨 색인을 고쳤다. 발행 라벨의 file:line 은 `40355b5` 기준이다.

- **녹화는 단순하게.** 인스타 = 사진 1장 «지금 발행» → «발행완료» 탭 → «게시물 보기»로 인스타에서 열기. 스레드 = 글(사진은 선택) «지금 발행» → «발행완료» → 스레드 앱.
  영상(릴스)·캐러셀·스토리는 같은 권한으로 되지만 심사에 필요 없어 «선택»으로만 적었다.
- **녹화 전에 운영에서 확인할 것.** `PUBLISH_VIDEO_PLAN.md` §4 는 «녹화 뒤에 합친다»였는데 녹화 전에 main 에 합쳐졌다.
  0093 이 운영에 적용돼 있어야 작성기가 올리기·저장을 한다(글만 있는 스레드 글도). 그다음 «지금 발행» 리허설을 채널마다 한 번
  (같은 문서 «손으로 해 보는 시험» B-5·C-10) — 메타가 핀치의 서명 URL 을 받는지도 이것으로 처음 확인된다.
- **발행 중 덮개(`40355b5`).** «지금 발행하기»를 누르면 작성 카드 전체가 «인스타그램에 올리고 있어요»·«스레드에 올리고 있어요» 덮개로 가려지고 초가 올라간다.
  예전 «발행 중…» 버튼 글자·안내 한 줄 대신 이것을 녹화 장면 10(인스타 영상 3·스레드 content_publish 영상)에 적었다.

## 사장님이 정하거나 확인할 것 (초안에서 모음)

1. **자동 DM 시연용 두 번째 인스타 테스터 계정** — 심사자가 댓글을 달 계정. 미리 달아 둔 댓글은 6.5일이 지나면 못 쓰고 심사는 1~3주 걸린다.
2. **테스트 인스타 계정 이름 `sding.kr`** — 코드 주석에 경쟁 도구 이름과 같다고 적혀 있다. 모든 영상과 자격 증명에 나오므로 핀치 테스트 계정인지 확인하고, 필요하면 녹화 전에 사용자 이름을 바꾼다.
3. **`sding.kr` 팔로워 수** — 100 미만이면 인스타가 팔로워 지표를 안 줘서 홈 «팔로워»가 0 으로 보일 수 있다(영상에서 어긋나 보인다).
4. **광고 녹화의 실제 비용** — 캠페인을 다시 켜면 실제로 돈이 나간다. 일 예산을 작게.
5. **광고 녹화에 사장님 페이스북 이름·사진이 나온다** — 가릴지.
6. **`instagram_business_manage_messages` 쓰임새가 얇다** — 코드상 수신거부 답장 받기(messages 웹훅)뿐이다. 반려되면 자동 DM 은 나가지만 수신거부 답장이 안 들어온다.
7. **임시오픈 안내 문구의 «정식 런칭은 9월 중»** — 10월 1일부터 틀린 말이 된다(고객에게는 계속 뜬다).
